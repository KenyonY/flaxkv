# FlaxKV2 架构设计文档

## 项目概述

FlaxKV2 是一个高性能的键值数据库系统，提供类似于 Python 字典的接口来操作持久化存储。它基于 LevelDB 后端，支持本地和远程访问模式。

## 核心组件说明

### 1. FlaxKV (工厂类)

**位置**: `flaxkv2/__init__.py`

**职责**:
- 统一的入口点，提供工厂方法
- 自动检测后端类型（本地/远程）
- 根据参数创建合适的数据库实例

**关键方法**:
```python
FlaxKV(db_name, root_path_or_url, backend='local'|'remote')
```

### 2. 本地后端

#### 2.1 RawLevelDBDict (推荐使用)

**位置**: `flaxkv2/core/raw_leveldb_dict.py`

**特点**:
- 高性能简化版本
- 直接写入 LevelDB，无缓冲机制
- 支持 TTL（过期时间）
- 支持嵌套字典（auto_nested）
- 实例复用机制

**核心功能**:
- 字典式接口：`__getitem__`, `__setitem__`, `__delitem__`
- 批量操作：`update()`, `items()`, `keys()`, `values()`
- TTL 管理：`set_ttl()`, `get_ttl()`, `cleanup_expired()`
- 嵌套字典：`nested(prefix)`

#### 2.2 LevelDBDict (功能完整版)

**位置**: `flaxkv2/core/leveldb_dict.py`

**特点**:
- 功能更丰富但性能略低于 RawLevelDBDict
- 支持布隆过滤器
- 支持索引管理
- 支持 TTL
- **注意**: 性能测试显示在 SSD 环境下，缓冲机制导致性能下降 30-87%
- **建议**: 对于大多数场景，推荐使用 RawLevelDBDict

### 3. 远程后端

#### 3.1 RemoteDBDict (客户端)

**位置**: `flaxkv2/client/zmq_client.py`

**特点**:
- 基于 ZeroMQ REQ socket
- 客户端负责序列化/反序列化
- 自动重连机制
- 超时控制
- 重试机制

**通信协议**:
```python
# 命令格式
[命令类型, 数据库名称, 参数...]

# 响应格式
[状态码, 数据]
```

#### 3.2 FlaxKVServer (服务端)

**位置**: `flaxkv2/server/zmq_server.py`

**特点**:
- 基于 ZeroMQ ROUTER socket
- 支持多客户端并发
- 只处理二进制数据（不序列化）
- 数据库实例管理
- 统计信息收集

**支持的命令**:
- `CONNECT`: 连接数据库
- `GET`: 获取键值
- `SET`: 设置键值
- `DELETE`: 删除键
- `KEYS/VALUES/ITEMS`: 批量查询
- `UPDATE`: 批量更新
- `PING`: 健康检查

### 4. 嵌套字典

#### NestedDBDict

**位置**: `flaxkv2/core/nested_dict.py`

**设计理念**:
- 基于 LevelDB 的 `prefixed_db` 功能
- 每个字段独立存储，避免频繁序列化整个字典
- 修改单个字段只序列化该字段的值
- 支持递归嵌套

**使用场景**:
```python
db = FlaxKV("mydb", auto_nested=True)
nested = db.nested("user:1")
nested['name'] = 'Alice'  # 只序列化 'Alice'
nested['age'] = 30        # 只序列化 30
```

### 5. 序列化系统

**位置**: `flaxkv2/serialization/`

**支持的类型**:
- 基本类型：使用 msgpack（高性能）
- NumPy 数组：特殊优化，保留 dtype 和 shape
- Pandas DataFrame：支持对象类型列
- 其他复杂对象：使用 pickle

**编码格式**:
```
[类型标识(1字节)] + [序列化数据]
```

### 6. TTL 管理

**位置**: `flaxkv2/utils/ttl.py`

**功能**:
- 键过期时间管理
- 自动清理过期键
- 支持默认 TTL
- 持久化存储（存储在同一个 LevelDB 中）

**存储格式**:
```
键: __ttl__:<原始键>
值: 过期时间戳
```

### 7. 实例管理

#### InstanceManager

**位置**: `flaxkv2/instance_manager.py`

**功能**:
- 数据库实例缓存
- 避免重复打开同一数据库
- 线程安全

#### AutoClose

**位置**: `flaxkv2/auto_close.py`

**功能**:
- 自动关闭数据库实例
- 程序退出时自动清理
- 支持上下文管理器

## 数据流图

### 本地写入流程

```
用户代码
   │
   ▼
db["key"] = value
   │
   ▼
RawLevelDBDict.__setitem__()
   │
   ├─► Encoder.encode(value)  ─► 序列化
   │
   ├─► TTLManager (如果有 default_ttl)
   │
   ▼
plyvel.DB.put()
   │
   ▼
LevelDB 文件系统
```

### 本地读取流程

```
用户代码
   │
   ▼
value = db["key"]
   │
   ▼
RawLevelDBDict.__getitem__()
   │
   ├─► TTLManager.is_expired()  ─► 检查过期
   │
   ├─► plyvel.DB.get()
   │
   ▼
Decoder.decode(bytes)  ─► 反序列化
   │
   ▼
返回 Python 对象
```

### 远程写入流程

```
用户代码
   │
   ▼
db["key"] = value
   │
   ▼
RemoteDBDict.__setitem__()
   │
   ├─► Encoder.encode(key)
   ├─► Encoder.encode(value)
   │
   ▼
ZeroMQ 发送: [CMD_SET, db_name, key_bytes, value_bytes]
   │
   │ (网络传输)
   │
   ▼
FlaxKVServer.handle_request()
   │
   ├─► 解析命令
   │
   ▼
RawLevelDBDict.put(key_bytes, value_bytes)
   │
   ▼
LevelDB 文件系统
   │
   ▼
ZeroMQ 响应: [STATUS_OK]
   │
   │ (网络传输)
   │
   ▼
RemoteDBDict 接收响应
```

## 设计特点

### 1. 性能优化

- **RawLevelDBDict**: 移除缓冲机制，直接写入 LevelDB，性能最优
  - 在 SSD 环境下可达 500K+ ops/sec
  - 比 LevelDBDict 快 30-87%（取决于操作类型）
- **序列化优化**: 针对不同数据类型使用最优序列化方案
  - 简单类型: msgpack（高效）
  - NumPy 数组: 二进制序列化
  - Pandas DataFrame: 优化的二进制格式
  - 复杂对象: pickle（兼容性）
- **嵌套字典**: 避免频繁序列化大对象
- **实例复用**: 避免重复打开数据库

**性能建议**:
- ✅ 推荐使用 RawLevelDBDict（默认）
- ✅ SSD 环境下性能最佳
- ⚠️ LevelDBDict 的缓冲机制在现代硬件上可能是负优化
- 📊 详细性能分析见 `doc/performance/PERFORMANCE_ANALYSIS.md`

### 2. 易用性

- **字典式接口**: 完全兼容 Python dict API
- **自动类型检测**: 自动选择合适的序列化方案
- **自动关闭**: 程序退出时自动清理资源
- **上下文管理器**: 支持 `with` 语句

### 3. 可靠性

- **原子操作**: LevelDB 保证写入原子性
- **线程安全**: 使用锁保护并发访问
- **TTL 持久化**: 过期时间持久化存储
- **错误处理**: 完善的异常处理机制

### 4. 扩展性

- **插件式后端**: 易于添加新的存储后端
- **远程访问**: 支持分布式部署
- **多客户端**: 服务器支持并发访问

## 使用场景

### 1. 本地持久化缓存

```python
from flaxkv2 import FlaxKV

db = FlaxKV("cache", "./data")
db["user:1"] = {"name": "Alice", "age": 30}
```

### 2. 分布式键值存储

```python
# 服务端
flaxkv2 run --host 0.0.0.0 --port 5555

# 客户端
db = FlaxKV("mydb", "127.0.0.1:5555", backend='remote')
db["key"] = "value"
```

### 3. 临时数据（带 TTL）

```python
db = FlaxKV("temp", default_ttl=3600)  # 1小时过期
db["session:123"] = {"user_id": 1}
```

### 4. 嵌套数据存储

```python
db = FlaxKV("users", auto_nested=True)
user = db.nested("user:1")
user['name'] = 'Alice'
user['email'] = 'alice@example.com'
```

## 安全考虑

### Pickle 序列化风险

FlaxKV2 对复杂对象使用 pickle 序列化，这存在安全风险：

- **风险**: pickle.loads() 可以执行任意代码
- **影响**: 恶意数据可能导致代码注入
- **缓解措施**:
  - 只在可信环境中使用
  - 避免从不可信来源加载数据
  - 生产环境建议只存储简单数据类型

### 远程访问安全

ZeroMQ 服务器默认无加密和认证：

- **风险**: 数据明文传输，无访问控制
- **影响**: 敏感数据泄露，未授权访问
- **缓解措施**:
  - 仅在可信网络中使用
  - 使用防火墙限制访问
  - 通过 VPN 或 SSH 隧道连接
  - 监听 127.0.0.1 而非 0.0.0.0
